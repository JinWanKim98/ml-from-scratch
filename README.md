# ML From Scratch — preprocessing and a categorical decision tree

Coursework implementing preprocessing with pandas and a categorical ID3 decision tree without a machine-learning library. A follow-up notebook compares the tree with scikit-learn and examines a minimum-leaf-size stopping rule.

## Preprocessing observations

Text such as `__10000__` in a numeric column is not counted as missing until conversion exposes it. Median imputation can create ties at a quantile boundary, so nominally equal-frequency bins can have unequal counts. The notebook also fills some customer-level values using other records for the same customer.

That customer-based fill is a retrospective cleaning exercise. It may use later months, assumes the relevant field is stable, and is not a leakage-safe real-time credit prediction pipeline. No downstream predictive performance is claimed for notebook 01.

## Tree comparison

Car Evaluation enumerates 1,728 categorical combinations. The custom implementation uses multi-way splits and majority fallback for unsupported branches. The comparison records the number of training examples behind a validation prediction, then checks several `min_samples_leaf` values for both implementations.

The earlier comparison selected the best setting on the test set. The revised notebook selects settings on an inner validation split and refits on the outer training partition before final evaluation. [Validation results](validation_results.csv) and [comparison results](comparison_results.csv) are generated by the notebook.

In this rerun, validation selects `min_samples_leaf=1` for both trees. The final custom ID3 accuracy is **87.57%**, versus **97.40%** for scikit-learn. The validation-selected ID3 is therefore the baseline itself: the earlier claim that selecting a minimum of 2 reliably improves it is not supported by this validation split. Reporting that outcome is part of the comparison.

![Validation sweep and final results](images/id3_vs_sklearn.png)

Small-support leaves can be a useful diagnostic, but their error rates also depend on how difficult those regions are. Changing a stopping rule changes the entire tree. A gain from a larger minimum does not isolate one-row leaves as the sole cause of a performance gap. scikit-learn also exposes node sample counts; this inspection is not possible only in custom code.

## Limits and maintenance

The custom tree accepts categorical inputs and implements no pruning. The same minimum-leaf setting constrains a multi-way split differently from a binary split. One historical outer split was reused and had already been inspected, so the corrected evaluation is not an untouched external benchmark; repeated or nested validation would be stronger.

Portfolio maintenance moved parameter selection off the outer test set, replaced unsupported causal explanations with diagnostic findings, and retained the course/source attribution. The original two learning notebooks remain separate from the later comparison.
